# Classic command and screen interaction audit

Audited against the checked-in original C source on 2026-10-30. This covers movement input, player production/investment, B bombardment, P? planetary assault, B? fleet battles/withdrawal and immediate enemy combat responses. Enemy decisions/investment now follow ClassicEnemyAI.md; normal ending/scoring now follow ClassicEndgame.md; persistence remains separate. See [combat audit](ClassicCombat.md) for B/B?/P?, and [encounter progression](ClassicEncounters.md) for the corrected G/space deadlock.

## Command inventory

The [enemy expansion milestone](ClassicEnemyAI.md) adds no movement command letters. After player G/space (or declined Q), initialized Classic games now run original enemy orders before movement, then existing combat and both owners' ordered investment/research. Visible E Arrive/E Depart letters obey C's player-presence checks. Enemy colonies are no longer an unsupported investment boundary. The C wandering index defects are corrected to select the actual reachable star and execute the original split; see ClassicEnemyAI.md.

## Input, cancellation and screen findings

- `input.c:get_line` uppercases and echoes characters, supports backspace and returns immediately at 25 characters, without consuming a following Enter. The C# loop now does the same. Backspace at the start safely leaves the buffer empty. CRLF in redirected input is treated as one Enter. EOF exits at every prompt. Bare Enter and Escape at the main movement prompt are illegal commands in C, not cancellation commands.
- `get_token` consumes a numeric prefix and returns the following character; S/T/R ignore the numeric value. For example, `2A 3B` selects A and B once each. Whitespace and blank/all handling now follow this token sequence rather than treating digits as object IDs. Invalid report selectors safely produce no rows; C's unsafe out-of-bounds cases are not reproduced.
- `send_tf` rejects invalid/nonexistent fleets, travel already begun or withdrawn, and blasting before asking for the destination. It clears withdrawal for accepted orders. `set_des` cancels pending travel before reading the replacement star. `FleetSystem.PreparePlayerCourse` owns this state change; `SetCourse` reuses it. Thus invalid replacement input and EOF after preparation leave the previous course cancelled. The debug shell still validates identifiers before calling Core, preserving its existing invalid-input behavior.
- `set_des` shows `(Cancelling previous orders)`, `to star:`, Euclidean `distance:`, and `eta in NN turns.` or `Tf remains at star.`. Presentation calculates distance only for the transcript; range, ETA and order rules remain in Core. Range failures retain the source error and cancelled course.
- `quit` does not undo `inputplayer`'s `fin=TRUE`. Consequently declining quit still advances the same Classic movement/economy phase as G. It is explicitly regression tested; the current combat/AI/endgame slices follow their source audits.
- Cursor movement in C is absolute positioning of prompts and panes, not player-controlled map navigation. The existing terminal boundary now supports cursor positioning and cache invalidation directly; there is no new input abstraction. Typed prompt text and the terminal cursor agree. Console resizing/snapshot fallback invalidates stale row caches.
- `movement.c:fleet_explore` shows fleet/star, loss counts in t/s/c/b order or `No ships destroyed.`, a surviving-star report, and `Press any key to continue`, including safe exploration. Player arrival glyphs and the displayed turn refresh automatically. `arrivalsShow` uses `P Arrive: ` with star letters aligned to the right. Known arrivals do not prompt for exploration again.

## Deliberate limits and remaining differences

- G/space and declined Q run the supported Classic phase, with mandatory fleet combat and immediate enemy/player planetary attacks before investment and again after due investment, then the shared clock. Unresolved interactions retain a playable B?/P? prompt or pause; they do not return to movement commands. Enemy orders/investment are now implemented within ClassicEnemyAI.md boundaries; victory/defeat/endgame now follow ClassicEndgame.md. See [encounters](ClassicEncounters.md) and [economy boundaries](ClassicEconomy.md). Enemy arrival/departure letters are implemented only where player presence permits observation.
- Core movement completes before UI exploration pauses; investment and clock increments now wait until acknowledgements finish. C pauses inside each arrival, so later fleets' positions can differ on that intermediate screen. UI inference adds no RNG draws or changed exploration rules. Exact intra-movement interleaving remains deferred.
- Report pagination stays within the existing 17-row pane, keeping normal star blocks together and allowing longer blocks/colony reports to continue. C's cursor bookkeeping sometimes writes down to rows 21/24, overlaps lower panes, pauses on lookahead after a final report, or fails to paginate T. Those terminal defects are not reproduced. The last visible page remains on EOF; acknowledgement keys are consumed as acknowledgements, not movement orders.
- Original monochrome-vs-color differences and line-based startup remain as documented in [Classic terminal](ClassicTerminal.md). Screen snapshots reserve column 80 to avoid console wrapping. Control characters are not injected into composed rows. Physical arrow/function keys are ignored by the console adapter rather than reproducing `_getch` extended-key bytes as accidental commands.
- N/J use Core player fleet operations; the Classic X-only J defect is preserved. See [fleet commands](ClassicFleetCommands.md). L handles immediate landing/colonization/resupply with original refusals; see [landing](ClassicLanding.md). Fourth-year growth/production and player colony management follow [the economy audit](ClassicEconomy.md). B bombardment and P? assaults follow [the combat audit](ClassicCombat.md).

## Planetary assault command inventory

P? appears automatically when stationary player warships can attack enemy colonies after preceding fleet/enemy combat. G/space selects the enemy planet (automatic when sole) and attacking fleet (automatic when sole stationary fleet), then resolves a salvo. B breaks off without movement or a withdrawal flag. H shows help and pauses; M/S/T/C/R and J/N retain their original meanings. W, D, L, Q and ? are illegal here. Losses/capture and under-attack defenses refresh automatically; completion clears attack flags, checks revolt and consumes an acknowledgement before the turn continues. B? now supports O odds and W withdrawal as well as G/space, M/H/S/T/C/R and ?. Mandatory encounters cannot be bypassed with P? or movement B. See [encounter interactions](ClassicEncounters.md).

## Investment command inventory

During the original colony prompt (`A3>  4?`), quantity-prefixed A/B/C/I/M/S/T/R/V/W spend the colony's IU-derived budget, H shows investment help, *x spends the maximum permitted by its original item rule, + builds an offensive bundle, and - builds a defensive bundle. > reads a separate M/S/C/R report key. All are implemented in Core/Classic UI; G, Q and blank input do not skip an unpaid budget. Player construction is immediate, research reuses existing tables, and transport mobilization can abandon the colony. See [ClassicEconomy.md](ClassicEconomy.md) for costs, rounding, budget and allocation quirks, EOF/session behavior and the explicit enemy/combat boundaries.
