# Conquest Classic v1.0 gameplay completion audit

Audit date: 2026-10-30. Specification: checked-in `OriginalSource`, with the existing [command](ClassicCommandAudit.md), [enemy AI](ClassicEnemyAI.md), [economy](ClassicEconomy.md), [combat](ClassicCombat.md) and [endgame](ClassicEndgame.md) audits. This is a source/code/test review, not a claim of binary equivalence or a v1.0 release declaration. No commit, push or tag is part of this audit.

## Recommendation

**Ready for release-candidate validation of ordinary Classic gameplay.** The audited path runs from generated startup through development, conflict and legitimate endings. One confirmed startup hang was corrected. No remaining confirmed conversion blocker was found in the reviewed ordinary-game paths or tested playthroughs.

This recommendation has practical limits: seeded tests use fixed human policies, do not exhaust all galaxies/decisions, and do not establish balance. Physical Windows-console acceptance and more varied human play remain RC work. Explicit guards around undefined or nonterminating original C states remain in place; they are not silently skipped turns or substitute rules. Their disposition needs review if RC play reaches them. This report does not declare Classic complete.

## Confirmed blocker and correction

**Conversion defect: nonterminating galaxy generation on a valid dense small board.** With seed 1, width/height 4 and 16 stars, the actual `Game.GenerateStars` exceeded a 100,000-draw audit budget. A required-success regression then failed against the old code after 10,000 draws. This is the direct reproducer previously missing from the backlog.

`CRandRng` advanced its 32-bit LCG state, shifted it right one, and took the bounded remainder. Successive low-bit results for power-of-two x/y bounds were correlated; the duplicate-position retry loop could not reach enough cells. The source's unique-position sampling was implemented, but this bounded RNG output made it nonterminating. `OriginalSource/init.c:initconst` samples `rnd` coordinates until unused; `utils.c:rnd` uses the platform `rand`, not a specified cross-platform LCG stream.

The correction rotates the state by 16 bits before extracting a nonnegative 31-bit bounded value. Higher state bits now drive small bounded choices. It retains the existing LCG state transition, seed handling, one state step per request, bounds, and reproducibility; generation's draw order, rejection sampling and planet probabilities are unchanged. No attempt limit, fallback placement or AI substitution was introduced. **Previously recorded seeded maps/outcomes change.** Exact C/C# RNG sequence identity is not an acceptance requirement for this audit.

Six regression cases fill 4×4 (seeds 1/7/41), 2×2, 1×8 and 8×1 boards within a bounded test draw budget, check uniqueness/coordinates/board links, and repeat identical generated planet/position data. The production generator has no test-budget logic. All pre-existing 736 tests also pass with the correction; no fixture expectations were weakened or seeds replaced.

## Remaining boundaries and acceptable limitations

- **Original unsafe states, explicitly isolated:** no reachable scout or withdrawal destination can make C rejection-sample forever; no candidate transport planet/warship destination can leave invalid or uninitialized selections; unchecked fleet allocation can use dummy slot zero. Owned zero-capacity growth and overflowing arithmetic are undefined. Existing guards report these states and retain partial failures without replaying RNG/orders. No fallback intent was established from the source. None occurred in the 32 paired ordinary-game runs. This is bounded evidence, not proof that no normal play can ever reach one.
- **Reviewed source interpretations:** wander selects the actual rnd(count)-th reachable star, correcting uninitialized `slist[0]` and advancing past the selected entry. Original J still checks only X because C compares Y with itself. These documented choices were not changed here. Correcting J would require a separately reviewed gameplay decision.
- **Terminal adaptations:** monochrome output; 79 printable columns to avoid wrapping; safe pagination rather than overlapping panes; ignored function-key bytes; EOF exits; snapshot fallback for redirected/small consoles. Startup remains line-oriented with a zero-based selection map, while gameplay reports use original one-based coordinates. No welcome pause or identical startup-screen transcript is claimed. These do not omit a gameplay decision.
- **Exploration pauses:** Core completes fleet movement before displaying individual arrival acknowledgements. The original pauses within movement. Intermediate screens may therefore show later fleets already moved; economy and year advancement still wait for acknowledgement. Exact intra-movement presentation is deferred, without changing exploration loss rules.
- **Compatibility boundaries:** fixed Classic-scale map/fleet limits and original heuristics remain. The development shell's legacy render/snapshot adapters are not the Classic gameplay renderer. Partial snapshot restoration is not presented as Classic save/load. A compiled original executable and physical console comparison were not available for this audit; source-derived rule and screen fixtures provide the comparison evidence.

These boundaries should be visible in RC review. A newly reproduced stoppage or incorrect rule is a blocker to investigate, rather than justification to disable a guard.

## Explicitly deferred modernization

Color enhancements, expanded galaxies, improved enemy strategy/balance, save/load, new rules, graphical interfaces and architectural refactoring are not unfinished Classic gameplay for this audit. No such work was implemented. Exact platform PRNG stream identity is also not required; deterministic replay within this implementation is tested.

## Validation results

- Baseline: **736 passing Release tests** before audit changes.
- Final full suite: **775 passed, zero failed/skipped**, including 39 added audit cases. Command: `dotnet test Conquest.sln -c Release --no-restore`. Normal Release binaries are rebuilt by this command. A separate Release output directory also passed the full 769-test intermediate suite and the final 39-case audit filter.
- **32 ordinary generated seeds (1–32), each played twice**, using real Classic initialization, a nonenemy habitable home, C/2S/2R purchases, landing, repeated turns, continuing mandatory battles and original defensive/weapon investments. No state/RNG budget was exceeded and no unsupported guard was bypassed. Endings took **3–80 completed turns**: 27 player-overwhelmed, five player-eliminated; all enemy wins under this intentionally passive human policy. Paired runs compare result, player/fleet/research state, planetary development and RNG count.
- One run per seed exercised **80 fleet battles, 134 enemy attack pauses and 392 production cycles**. Counts describe this script/seed set, not statistical guarantees. Seed 28 reached 80 completed turns; seed 24 was eliminated after 57 turns of sustained conflict. Early legitimate defeat is allowed.
- Existing paired generated attack playthroughs (seeds 1/17) and controlled 60-turn enemy-development simulations (1/7/41) also pass. The latter reach the configured limit with developed enemy colonies and repeatable results. Existing encounter, withdrawal, hidden-information and economy tests remain enabled.
- Added a controlled late-game continuation that moves a fleet to the last enemy colony, captures it through the actual planetary attack path, completes the turn and obtains **player victory by enemy elimination**, with no score/RNG fabrication. Existing endgame tests cover defeat, draw, strict thresholds, time-limit/final-year behavior, quit and retained final screens.
- Redirected executable checks: generated startup → help/redraw/star/fleet/research reports → confirmed quit; generated startup → configured one-turn ending; separate debug-shell generation/map/quit. All exit 0, show the expected startup/ending where applicable and emit no enemy-stopped diagnostic or exception. Scripted terminal tests additionally cover commands, prompt cancellation/errors, movement, shared locations, refresh, combat/investment and final-screen acknowledgement. These process checks do not claim physical cursor/color validation.
- `git diff --check` passes. NuGet emits the existing NU1900 warning because vulnerability metadata cannot be retrieved; builds/tests succeed. No packages were changed.
